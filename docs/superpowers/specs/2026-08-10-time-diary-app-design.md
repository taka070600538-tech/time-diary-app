# 時間管理ダイアリー（Claude Code版）設計書

作成日: 2026-08-10

## 目的

Google AI Studioで作成した「時間管理ダイアリー」を参考に、既存のPWA＋GitHub自動保存基盤
（app-sync / app-data）に乗る形で再実装する。参考アプリとの最大の違いは、
**時刻項目と自動計算区間をユーザー自身が編集できる**こと。

## 要件（確定事項）

1. 参考アプリの機能（タイムライン入力・自動計算・分析グラフ・CSVダウンロード・PWA化）を再現する
2. タイムラインの時刻項目（追加・名前変更・削除・並べ替え）と、
   自動計算区間（開始項目→終了項目のペア定義）をアプリ内で編集できる
3. データ保存は既存の中央ホスト型基盤を使う
   （app-sync v1 sync.js → app-data/time-diary/backup.json、1日1回自動＋手動保存）
4. PC側では毎日の自動pull後、Obsidianのデイリーノート（01_日記/YYYY-MM-DD.md）へ
   見出し＋表形式で転記する

## 全体構成

- 公開リポジトリ `time-diary-app`（GitHub Pages公開: https://taka070600538-tech.github.io/time-diary-app/）
- ビルド不要の静的PWA:
  - `index.html` / `style.css` / `manifest.json` / `sw.js` / `icons/`
  - `js/app.js`（起動・タブ制御）、`js/store.js`（データモデルとlocalStorage永続化）、
    `js/timeline.js`（入力タブ）、`js/stats.js`(分析タブ)、`js/items.js`（項目編集タブ）、
    `js/csv.js`（CSV生成）、`js/calc.js`（区間計算・集計の純粋ロジック）
- 入力はlocalStorageに即時保存。GitHubへは `https://taka070600538-tech.github.io/app-sync/v1/sync.js`
  を動的importし、`initDailyBackup({ appId: 'time-diary', collect, restore })` で
  1日1回自動バックアップ。設定エリアに `renderSyncSettings` の共有UIを置く
- PATは同一オリジン（taka070600538-tech.github.io）のlocalStorage共有により、
  既存アプリで設定済みなら入力不要
- sync.jsのimport失敗時は静かにスキップ（基盤の設計どおり）。sw.jsのキャッシュ対象に
  sync.jsのURLを**含めない**

## データモデル

```json
{
  "version": 1,
  "items": [
    { "id": "prev-sleep", "label": "前日の就寝" },
    { "id": "wake", "label": "起床" }
  ],
  "intervals": [
    { "id": "sleep", "label": "睡眠時間", "start": "prev-sleep", "end": "wake" }
  ],
  "days": {
    "2026-08-10": {
      "times": { "prev-sleep": "22:30", "wake": "06:30" },
      "note": "特記事項テキスト"
    }
  }
}
```

- `items` は表示順のとおりの配列。初期プリセットは参考アプリと同じ16項目:
  前日の就寝 / 起床 / 朝の運動開始 / 朝の運動終了 / 朝食準備開始 / 朝食準備終了 /
  朝食終了 / 外出 / 勉強開始 / 昼食終了 / 勉強終了 / 帰宅 / 入浴終了 / 夕食終了 /
  就寝準備 / 就寝
- `intervals` の初期プリセットは4つ:
  睡眠時間（前日の就寝→起床）/ 朝の運動時間（朝の運動開始→終了）/
  朝食準備（朝食準備開始→終了）/ 勉強時間（勉強開始→勉強終了）
- 区間計算は同一日の `times` 同士で行い、終了<開始のときは日付跨ぎとして+24時間
- 記録は項目IDに紐づくため、項目名の変更で過去データは失われない
- 項目削除時は確認ダイアログを出し、その項目を使う区間も同時に削除する
  （過去の `days` の時刻値は残す=非破壊。項目を再作成しても同じIDにはならない点は許容）
- IDは `crypto.randomUUID()`（プリセットのみ固定スラッグ）

## 画面構成（3タブ）

### タブ1: タイムライン入力
- 日付ナビゲーション: 前日 / 今日 / 翌日 / `<input type="date">`
- `items` の順に1行ずつ: 項目名、`<input type="time">`、「現在」ボタン（現在時刻セット）
- 区間の定義に該当する位置（終了項目の直後）に自動計算行をグレー表示
  （「--:-- → --:--」と所要時間。両端が入力されたら即時更新）
- 特記事項の `<textarea>`
- すべての変更はlocalStorageへ即時保存

### タブ2: 分析・グラフ
- `intervals` ごとに: 統計カード（記録のある全日程の平均、今週=月曜起点の合計と日数）
  ＋直近7日間の棒グラフ
- グラフは外部ライブラリなしのインラインSVG。区間編集に自動で追従
- 実装前に dataviz スキルを読んでから着手する

### タブ3: 項目の編集
- 項目リスト: 名前変更（インライン編集）、上下ボタンで並べ替え、追加、削除（確認つき）
- 区間リスト: 名前、開始項目・終了項目のプルダウン、追加、削除
- バリデーション: 区間の開始・終了に同じ項目は選べない

### 設定エリア（タブ外・ヘッダーまたはフッター）
- `renderSyncSettings` によるバックアップUI（トークン・今すぐ保存・GitHubから復元）
- CSVダウンロード（全日程: 日付, 各項目の時刻, 各区間の分数, 特記事項。
  ヘッダーは現在の項目・区間定義に従う）
- 全データ初期化（確認つき、プリセットに戻す）

## PC側: デイリーノート転記

- 既存の毎日pullタスク AppDataGitPull が実行する
  `app-sync/tools/app-data-pull.ps1` に転記ステップを追加する
- pull後、`app-data/time-diary/backup.json` を読み、**前日以前**で
  `days` に記録があり、かつデイリーノートに「## 時間管理ダイアリー」見出しが
  無い日をすべて転記する（見出しの有無が転記済み判定＝二重追記防止）
- デイリーノート（`01_日記/YYYY-MM-DD.md`）が無ければ新規作成、あれば末尾に追記
- 転記フォーマット:

```markdown
## 時間管理ダイアリー

| 項目 | 時刻 |
| --- | --- |
| 起床 | 06:30 |

**睡眠時間**: 7時間30分 ／ **勉強時間**: 5時間00分

### 特記事項
（メモの内容。無ければこの節ごと省略）
```

- 時刻が未入力の項目は表から省略する
- Markdown生成ロジックはNode（`tools/transcribe.mjs`）に置き、PowerShellからは
  `node tools/transcribe.mjs` を呼ぶだけにする（PS1内の日本語リテラル問題を回避し、
  node:testでテスト可能にするため）
- ps1の保存はBOM付きUTF-8にする（既存スキルの落とし穴対策）

## テスト

- `node:test` で純粋ロジックをテスト:
  - 区間計算（通常・日付跨ぎ・片側未入力）
  - 週集計・平均・直近7日抽出
  - CSV生成（項目定義の変更に追従、日本語・カンマ・改行のエスケープ)
  - 転記Markdown生成（表・区間まとめ・特記事項省略・転記済み判定）
- manifest.json / icons / sw.js の整合性テスト（宣言アイコンの存在・実寸一致・ASSETS包含）

## エラー処理

- オフライン時: localStorage保存のみで動作継続。バックアップは次回オンライン起動時に再試行
- バックアップ・復元の失敗はUI上のステータス表示で通知（基盤のメッセージをそのまま表示）
- 転記スクリプトの成功・失敗は `pull-log.txt` に追記

## スコープ外（YAGNI）

- Googleログイン・独自クラウド
- 複数プリセット（平日用・休日用）の切り替え
- グラフの期間カスタマイズ（直近7日固定）
- リアルタイムの端末間同期（1日1回バックアップ＋手動ボタンで足りる）
